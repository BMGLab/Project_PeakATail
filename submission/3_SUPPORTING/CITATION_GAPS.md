## G1 — BLOCKING. The "curated literature shortening panel" has no recorded literature

**Token:** `[[CITE: literature sources of the spermatogenesis 3′UTR-shortening gene panel]]`
**Location:** MAIN.md line 122 (Results, Fig 5 spermatogenesis section). Also carried, uncited, by
`manuscript/00_draft/sec_results_2.md:32`, the Fig 5d legend, the Key Points bullet in MAIN.md
line 53, and the Discussion negative-results summary.
**Status:** `UNRESOLVED`. No reference recorded, none guessed.

**Why it could not be resolved.** The panel is a hard-coded Python list with no provenance comment,
at `scripts/manuscript_figures/spermatogenesis_control_steps/step7_genes.py:70-71`:

> Cstf2t, Ybx2, Prm1, Prm2, Prm3, Tnp1, Tnp2, Smcp, Odf1, Akap4, Ppp1cc, Crem, Camk4, Hnrnpa2b1,
> Ldhc, Meig1, Acr, Acrv1, Gapdhs, Spata19, Oaz3, Tssk6, Pgk2, Hils1, Elavl1, Nsun7, Spem1

27 genes, of which 16 were measurable in both mice — the 16 the sentence reports on. I grepped the
whole working directory for a source: `literature panel`, `shortening panel`, `LIT`, `PANEL_GENES`,
`Nsun7`, `Spata19`, and the string `curated`. Every hit is either the code above, a figure caption,
or a manuscript record that *restates* the result (`manuscript/18_spermatogenesis_final.md:45`,
`manuscript/06_roadmap.md:75`, `manuscript/21_paper_architecture.md:444`). **No file in the repository
names where the panel came from.**

This is not a formatting gap. The sentence's rhetorical weight — a load-bearing negative result,
"a curated literature shortening panel … does not reproduce" — depends entirely on the panel being
a real literature panel. A referee who asks "whose panel?" must get an answer, and the list mixes
3′-end-processing *regulators* (Cstf2t, Elavl1, Crem, Camk4) with spermatid structural *targets*
(Prm1/2/3, Tnp1/2, Odf1, Akap4), which is not the shape of a single published shortening panel.

**What the PI / reference manager must supply — one of:**

1. The paper(s) the 27 genes were taken from, with which genes came from which. Then the panel
   claim stands as written and the citation goes in.
2. If the panel was assembled by hand from general spermatogenesis-APA knowledge rather than copied
   from a source: say so in the text. "A curated literature shortening panel" becomes something like
   "a hand-assembled panel of genes reported to shorten during spermatogenesis", and the sentence
   cites the general source(s) for the phenomenon rather than for the list. The negative result
   survives — it is just no longer a failure to reproduce someone else's published panel.
3. If neither can be supported: drop the panel leg. `manuscript/18_spermatogenesis_final.md:48`
   already anticipates this ("the literature-panel leg of Fig 5 is dropped or shown with these
   numbers"), and PI_DECISIONS.md B5 already holds the related manual PAS-to-gene check.

**Candidate sources, offered as leads only — NOT applied anywhere.** `li2016spermatogenesis`
(Li et al., BMC Biol 2016, doi 10.1186/s12915-016-0229-6) is in `references.bib` as the verified
citation for genome-wide 3′UTR shortening across mouse spermatogenesis, and is the most likely
origin of a shortening panel. **I did not verify that these 27 genes come from it, and it must not
be cited as the panel's source until someone checks the gene list against its tables.**

## G2 — DECISION. polyApipe has no peer-reviewed paper; a poster DOI is all that exists

**Token:** `[[CITE: polyApipe paper]]` ×4 (MAIN.md lines 59, 82, 147, 185).
**Status:** mapped to `harrison2019polyapipe`, which **is** verified — but read this before shipping it.

polyApipe is one of the four de novo competitors the paper benchmarks and the one it beats on the
two-truth hard-false-positive composite (15.10% vs 49.50%), so its citation is load-bearing.

What exists, verified 2026-09-02:

- The tool's own README (`https://raw.githubusercontent.com/MonashBioinformaticsPlatform/polyApipe/master/README.md`)
  gives no citation instruction. It says only: *"This poster on polyApipe was presented at Oz Single
  Cell 2019"*, linking `https://doi.org/10.7490/f1000research.1117076.1`.
- Crossref (`https://api.crossref.org/works/10.7490/f1000research.1117076.1`) resolves that DOI to:
  Harrison P, Williams S, Powell D, Albrecht D, Beilharz T, *"Tools for identifying and characterizing
  alternative polyadenylation in scRNA-Seq"*, F1000Research, 2019, Crossref type `posted-content`.
  Note the title does **not** name polyApipe.
- Web search for a polyApipe algorithm paper returned none; the tool is described in secondary
  sources as unpublished.
- `f1000research.com/posters/8-1142` returned HTTP 403 to this environment, so the poster's landing
  page was not read directly — the metadata above comes from Crossref, which is the authoritative
  DOI registry record.

**PI call needed:** (a) cite the poster DOI as-is; (b) cite the poster **and** the software repository
`https://github.com/MonashBioinformaticsPlatform/polyApipe` (pin the commit actually benchmarked —
the benchmark record should have it); or (c) cite the repository alone. Genome Biology accepts
software citation, so (b) is the defensible option and is what I would recommend. Whichever is
chosen, the Methods sentence naming polyApipe's version should point at the same object.

## G8 — MANUSCRIPT DEFECT (found 2026-09-03 during adversarial verification). The curated panel is 27 genes; "16-gene panel" misstates it

This is not a citation gap — it is a numbers-integrity defect discovered while chasing G1, and it
sits in text a referee will read.

**The facts, all traced:**

| source | says |
|---|---|
| `scripts/manuscript_figures/spermatogenesis_control_steps/step7_genes.py:70-71` | the hard-coded `LIT` list contains **27** gene symbols (counted) |
| `results/stage3_spermatogenesis_v2/REPORT_PROVISIONAL.md:290` | *"The **27-gene** curated panel ... has **16 genes measurable in both mice** under the depth guard"* |
| `results/stage3_spermatogenesis_v2/summary/gene_replication_summary.json:27` | `"n_measurable_in_both": 16` |
| `manuscript/figures/fig5_spermatogenesis.caption.md:35` | **correct, and now the clearest statement of it** (rewritten by the figure workflow at 00:30 on 2026-09-03): *"of the **16 genes** of the **27-gene** curated literature panel **measurable in both mice**, only 4 shorten in both"* — this is the phrasing MAIN.md's Key points and Discussion should adopt |
| `MAIN.md` Results body (line 122) | **correct**: *"of the **16 genes** of a curated literature shortening panel **measurable in both mice**"* |
| `MAIN.md` Fig 5 caption (line 268) | **correct**: *"of **16 measurable** literature-panel genes"* |
| `MAIN.md` Key points / Discussion | **WRONG**: *"a **16-gene literature panel** ... does not reproduce"* |
| `manuscript/18_spermatogenesis_final.md:45` | **WRONG**: *"The **16-gene** literature panel does not reproduce: of 16 measurable..."* |

So: **one panel of 27 genes, of which 16 were measurable in both mice.** The compressed phrase
"a 16-gene literature panel" silently converts the *measurable subset* into the *panel size*. The
long-form statements in the Results body and the figure caption are right; only the compressed
ones are wrong.

**Why it matters.** The non-reproduction of this panel is a headline negative result, quoted in the
Key points. As written, a referee who opens the code finds 27 genes where the paper claims 16 and
has to work out which number is real. It also makes the failure look worse than it is: "4 of 16
shorten" reads differently against a 27-gene panel with 11 genes unmeasurable than against a panel
that was only ever 16 genes.

**Who must act.** Whoever holds `MAIN.md` after the legend-sync lock lifts. Two touch points:
the Key points bullet and the Discussion sentence. Either restore the full form ("a curated
27-gene literature panel, 16 of them measurable in both mice, does not reproduce") or drop the
count ("a curated literature panel ... does not reproduce"). `manuscript/18_spermatogenesis_final.md`
carries the same error and is the likely origin.

`submission/cover_letter.md` inherited the wrong phrase and **has already been fixed** — it now
reads "a curated literature panel", which is true under either reading.

**Interaction with G1.** G1 remains blocking and unchanged: whatever the panel's size, no source is
recorded for it anywhere in the repository. G8 is about stating its size correctly; G1 is about
being able to cite it at all. Fixing G8 does not resolve G1.
