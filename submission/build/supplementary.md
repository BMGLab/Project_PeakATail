## Fig S1 | The datasets behind every headline number, with the poly(A) clip rate

**(a)** Per-library table for the four benchmark arms and the cohort: chemistry, upstream pipeline, read-2 length, cells, and the identical v2 parameter block (108 recorded parameters; the only library parameter is `--seq-len`, the R2 read length). An em-dash means no verified measurement exists and the value is omitted rather than approximated (testis clip rates; testis/cohort per-BAM read counts; the cohort clip rate — its in-run 0.015% warning was a head-of-chr1 sampling artefact and is never repeated as fact). **(b)** Clip rates where a verified value exists. The genome-wide qualifying rate on PBMC 10k v3 is 0.5730% (3,195,067 / 557,564,408 accepted cell-barcoded reads) — the corrected constant, superseding the 1.152% docstring figure. Hatched bars are the caller's head-sample QC estimator (first 200,000 cell-barcoded reads of a coordinate-sorted BAM), which reads 2.2565% on PBMC where its own criteria measure 0.5364% genome-wide (~4.2× head bias): estimator values are comparable only with each other, never with the genome-wide bar. pbmc4k's estimator value is 1.64× donor 1's — the evidence channel is richer on donor 2. Cohort scope: 17 GSM libraries = 14 patients; the pre-registered primary excludes MetBone (15 GSMs = 12 patients); cells shown are the Stage-3 curated set (29,063) and its label-confirmed subset (18,651; 64.2%), not a CellRanger estimate.

## Fig S2 | v2 peak-call QC and the tier-2 cleavage-offset census

**(a)** Tier composition of every final v2 arm, with every count naming its arm: PBMC IP arm 333,920 calls (tier 1 167,565 / tier 2 166,355 scored), default 46,524 (P@100 0.7062); mice defaults 26,255 / 26,526 (0.7450 / 0.7572); single-molecule share of tier 1 is 72.2% on the PBMC IP arm and 72.1% on the no-IP arm (the value the text quotes). The no-IP ≥2-molecule file is post hoc and is not the default. **(b)** Tier-2 calls are wide intervals (medians 371 / 259 / 248 bp); tier-1 calls are 1-bp clip-anchored points. **(c)** Default calls per gene. **(d)** Distinct-clip-molecule distributions; selecting BED score ≥2 reproduces the default exactly (asserted per arm). **(e–g)** The ~90–105 nt tier-2 coverage offset (10x R2 coverage runs out before the poly(A) junction), measured on the development slices: four independent estimates agree (tool auto-offset 103 PBMC / 87 mouse; post-hoc argmax +95 on atlas P@10 and on Kinnex t5 P@10 — t5 = ≥5 long-read records at the terminus, not de-duplicated UMIs); the signed-distance mode moves to ~0 when corrected, and the tier-1 control sits at +0, so the offset is real and tier-2-specific. **Boxed negative disposition:** correcting it triples tier-2 P@10 but fails every pre-registered acceptance criterion (atlas-agreement P@100 remains ~0.085 vs null 0.028 on PBMC, no recall gain, internal-priming decoy rate more than triples); nothing is adopted — the disposition is to report inferred cleavage, not to move calls. Caveats: the census ran on development slices (the PBMC slice is clip-richer than the genome), so whether the offset holds for all 166,355 full-BAM tier-2 sites is an inference, not a measurement; the underlying sweep is provisional pending its own verifier.

## Fig S3 | Why the benchmark is built this way: regimes, chance and one reconciled null

**(a)** Against the 18,432,135-entry PolyASite dump with whole-peak-interval matching, five peak-calling strategies scored 0.996–1.000 (spread <0.004) while width-matched shuffled peaks already scored 0.62–0.75, and the two retired figures computed different nulls for the same arm (0.615 vs 0.753) — under that regime the benchmark can rank nothing. Scored at the strand-matched 3′-most base against the curated PolyASite 2.0 representative sites, the same five arms separate (P@100 0.355–0.492) over one reconciled null (0.020–0.024). **(b)** Reference density recomputed on the curated point reference: 2.26% of gene-body bp lies within 100 bp of a same-strand curated site, and the measured null mean (0.0219) equals that local density within 3% — chance in this benchmark *is* reference density, which is why the null is indispensable. **(c)** The same `score_tool.py` null accompanies every verified score TSV: the pre-registered default scores 0.7062 / 0.7450 / 0.7572 against nulls of 0.0217 / 0.0139 / 0.0138 (33–55× chance), and every competitor is scored with its own identically built null. Caveats: panel a's left group is the retired record, shown solely as the discrepancy being reconciled — none of its values may be quoted as benchmark results; the null≈density ratio (0.97 at 100 bp) is a consistency observation of this recompute, not an independently verified claim; the density denominator is the merged gene-body space the null shuffle actually uses (1.80 Gb), not the whole genome; scUTRquant is catalog-based and unranked; SCAPTURE mouse 2 is not plotted (site-level run scored 0.672; only mouse 1 carries a verified null-bearing row).

## Fig S4 | Second-donor validation: the unchanged default on pbmc4k (pre-registered)

Pre-registered before any pbmc4k number existed (driver frozen 19 minutes before the caller started); run on the identical frozen code, scorer, atlas and nulls; 107 of 108 recorded parameters identical, the one change being `--seq-len` 91→98, a library descriptor. **(a)** Gate P@100 ≥ 0.50: PASS at 0.8279 (38× its null) — the gate now holds on four libraries; the ≥1-molecule arm again has the higher F1_det (0.2635 vs 0.1948), so ≥2 molecules remains a reliability choice, not the F1 optimum. **(b)** Cross-donor concordance per the pre-registered protocol, both directions, never one alone: 84.2% of donor-2 default calls have a strand-matched donor-1 call within 100 bp (81.3% at 25 bp; ~361× the genic-shuffle null); the reverse direction is 39.9% against its 44.4% arithmetic ceiling (donor 1 emits 46,524 calls to donor 2's 20,672 — call-count arithmetic, not disagreement). **(c)** The matched-call-count control, drawn so it cannot be buried: donor 1's default cut to donor 2's call count by any route scores P@100 0.886–0.907 with R_det 0.112–0.124, dominating donor 2 on both axes — donor 2's higher headline atlas-agreement precision is an operating-point effect. **Precision generalises; it does not improve.** Caveats that travel: a second library, chemistry and CellRanger version, only presumptively a second individual (10x publishes no donor identifier); recall is genuinely lower on donor 2 (R_det 0.1104 vs 0.1754; survives every denominator swap, and the clip channel was 1.64× richer on donor 2, so channel poverty is no excuse); no claim about v2-vs-v3 chemistry as such.

## Fig S7 | The pre-registered trusted-novel definition and its failure (negative result)

Input: the final PBMC 10k v3 precision default (46,524 sites on primary contigs). The definition, committed before any number existed — clip-supported ∧ ≥2 molecules ∧ not internal priming ∧ canonical hexamer at −40..−5 ∧ ≥100 bp from any PolyASite 2.0 site (PolyA_DB, hg19-only, could not be used) — yields 7,259 trusted-novel sites (15.6%). Truth: Kinnex x3p poly(A)-verified 3′ ends (different donors), hit = within 25 bp, same strand, at ≥5 supporting long-read records at the terminus (not de-duplicated UMIs). **(a)** The funnel with per-stage concordance: input 0.765 → hexamer 0.811 → atlas-novel 0.485 → strong hexamer 0.502; the atlas-novelty stage is what moves concordance; dashed line = the 0.70 target. **(b)** Concordance vs truth stringency, with the atlas-known hexamer-pass complement (0.894 at ≥5 records) calibrating the ceiling and the 10-seed shuffled null (0.007) as a band. **(c)** Feature classes (trusted-novel 69.4% intronic) and Kinnex internal-priming-decoy proximity (27.0% vs 7.6% for the atlas-known hexamer-pass complement). **(d, boxed, post hoc)** Concordance by feature class and molecule support — exploratory only; never call a de novo site "trusted" on its strength. Caveats that travel: this is a negative result and is written as one — 0.485 vs the ≥0.70 target, missed under every truth choice at the pre-registered 25 bp window (GEM-X 0.515, pooled 0.582; the 50/100 bp pooled values are not the pre-registered window); donor mismatch cannot explain the gap (the atlas-known complement scores 0.894 on the same truth), though truth is site-level and donor-mismatched, which caps the attainable fraction; enrichment over the null (65–179×, empirical p at the 1/11 floor) does not rescue an absolute-fraction target; the hexamer adds +0.046 overall but nothing among atlas-novel sites (hexamer-fail 0.487) — the novelty criterion selects the sites the long reads see least; the residual class survives both internal-priming rules — added on top of the shipped filter, a Kinnex-style A-richness rule removes 31 of 46,524 default sites, a no-op — so the internal-priming diagnosis, chosen after seeing the data, remains a hypothesis (decoy-proximal sites are less concordant, 0.39 vs 0.52: a plausible mechanism, not a proven one); the v1→v2 change (0.521 → 0.485) is descriptive, not a test; single PBMC donor, single BAM.

## Fig S8 | Compute detail behind Fig 3d

**(a, b)** Every PBMC 10k v3 arm from the verified compute registry. Rule in force: never quote wall time without the concurrency disclosure — the v2 arm wall times (34:37 no-IP, 32:59 IP) were measured with all four benchmark arms running concurrently; the uncontended single run is 27:43 — and peak RSS is the production number: 293.7 GB (v1) → 12.53 GB (v2), 23.5×. v1 exceeded the pre-registered 150 GB stop signal and was profiled rather than shipped (a ≥300 GB node, ~1.4 cores despite `--threads 16`). Competitor caveats carried verbatim: scAPAtrap's 4:04:29 is a resumed run after an OOM-killed first attempt and understates a from-scratch run (12:58:50 total machine time, disclosed, not summed); scUTRquant's 30:45 sums two attempts; SCAPTURE's 12:14 sums its two mandatory stages with the annotation prebuild untimed; polyApipe and Sierra ran clean. **(c)** The fix confirmed at two other scales: the 17-library cohort (~224 GB of BAM) fell 9:06:26 → 1:06:26 (8.2×) at identical output (505,197 unified PAS on both codes), the mouse arms 1:01:09/1:01:48 → 14:10/16:00 with peak RSS 23.1/22.4 → 3.07/3.65 GB. **(d)** Why: profiling located the v1 peak in clustering (dense TF-IDF; four dense float64 copies of the cells × PAS matrix, 291 GB computed, 287.8 GB measured in isolation); the fix (sparse TF-IDF, per-(contig, strand) parallel calling, streamed cell-barcode filter) is byte-identical on 18/18 compared outputs.

## Fig S9 | Calibration deep-dive behind Fig 4

Same harness as Fig 4 (testis mouse 1; 20 shared label permutations; no permutation re-run — all panels read the verified TSVs, except the declared recomputation in b). **(a)** Per-stage-pair null p < 0.05 for all six configurations: no pair drives any verdict; the shipping configuration B0 (Fisher, cells, no marker pre-selection) spans 2.94–3.13% with 0/20 null runs carrying any q < 0.05 hit. **(b)** B0 stratified by a label-independent expression measure: every stratum is below the 5% nominal rate — never anti-conservative at any expression level (recomputed 2.5–4.0% under a declared binning; the verified range is 2.6–4.0% and the original bin edges were not persisted — stated caveat; the pooled rate reproduces the verified 3.03% exactly). **(c)** Reads-mode pseudoreplication: 20.3% vs 13.0% null p < 0.05 with pre-selection on, 9.6% vs 3.0% with it off, and ~1,500 false q < 0.05 hits per null run in reads mode even without pre-selection. **(d)** Permutation-calibrated q vs nominal BH q on the true runs; for B0 the permutation null is conservative and calibrated q adds hits (60,332 → 66,630; 46,230 after the effect floor). True hit counts are not comparable across marker modes (different tested universe and a different Fisher gene denominator). **(e)** The negative-binomial plug-in dispersion floor (10⁻⁴): in the pre-selection-off arm, 8.5% of null tests carry 67% of null q < 0.05 hits (13% in the marker arm). Rule that ships: whenever marker pre-selection or `nb_pairwise` is used, permutation-calibrated q is required. Caveats: single mouse, single tissue, very large true stage effects; the label-permutation null tests exchangeability under the global null only; KS rejects for every arm (discrete Fisher) and is reported, not gated; "calibrated" is the pre-registered operational rule, not a standard.

## Fig S10 | The dropped clustering claim, stated honestly

**(a)** PBMC 10k v3: clustering on all 275,370 PAS-site counts recovers GEX marker cell types (AMI 0.708, ARI 0.502) — but summing the same counts to 14,891 per-gene totals, discarding all site-level resolution, recovers them just as well (AMI 0.6978; k-matched 0.7878 vs 0.7602). Site resolution adds nothing, so the recovery is 3′-end expression signal re-encoded, not isoform choice; the positive result never appears without this ablation on the same axis. **(b)** The (dropped) positive result replicates: 17/17 Laughney libraries, median AMI 0.662 (range 0.367–0.779). **(c)** The retired parameter sweep's one durable finding: Leiden resolution dominates cluster count (+112.5% median, 17/17 datasets) while every annotation-trim knob is at least 8× smaller. Caveats that travel: the reference partition is marker-derived, not curated truth; per-site counts carry gene abundance, and panel a shows abundance suffices — no isoform-choice signal is demonstrated; concordance is scored on GEX-labelled cells only (median coverage 0.498; coverage does not drive agreement, ρ −0.34, p 0.18); no stage effect is claimed; the isoform-only usage-fraction spaces are excluded (mis-keyed matrices, re-run pending; the ablation verdict does not depend on them); `--min-pas-prominence` is proven byte-identically inert on the lambda strategies, so no prominence arm of the retired sweep could have been informative; the library-size bar's median must not be quoted alone (per-dataset range −41.7% to +93.3%); cluster count is a granularity proxy — nothing here says cell assignments are stable across knobs.

## Fig S11 | The pre-registration record, drawn so it can be audited rather than taken on trust

**(a)** Timeline. The original two-sided gate (P@100 ≥ 0.38 AND F1_det > 0.261) was fixed one day before the run it judged; the stale Stage-2 run failed it in full. The ≥2-molecule threshold was then examined in a sweep created 12 minutes after that FAIL was recorded — post hoc, full stop — and is disclosed as such: it informed the choice and is never cited as a result. The precision-first default and its P@100 ≥ 0.50 gate were committed (`0e27b1a`, 01:18:59, git-verified) 1:40:37 before the final arms started; the v1 run passed on all three call sets, and the v2 re-run (gates unchanged) passed again while the original 0.38 floor kept failing on every ≥1-molecule output — both facts shown, neither hidden. Three further pre-registrations followed, each written before its number existed: the prime adoption criterion, the second-donor test (driver frozen 19 minutes before the caller started) and the 3′UTR singleton promotion. Outcomes: pbmc4k PASS 0.8279; prime FAIL at Δ 0.000000 — a byte-identity, not a regression, because the criterion was drafted against a v2 default that never existed; singleton PENDING, flag default OFF. **(b)** The gate table drawn: every pre-registered gate, every arm, every value, every verdict — including both FAILs and the untested pre-registration. Caveats: markers for documents that record a date but no clock time sit at display positions, flagged in the audit TSV; Stage-2 values are quoted from their (superseded) record, everything else re-read programmatically from score TSVs; verdicts are encoded as glyphs, never colour alone.

## Fig S12 | Four versions of the caller on four libraries, scored once

shipped (pre-Stage-1, coverage-only) → v1 (`4efeb125`, clip-seeded) → v2 (`9dfdefb3`, + #96 + #97) → prime (`6954082d`, unmerged branch). **v2 is the manuscript's record; every prime value is exploratory with respect to the manuscript's gates.** Headline: prime's default reproduces v2's manuscript arm byte for byte (md5-identical call files on all four libraries), so the pre-registered adoption criterion FAILS with every Δ exactly 0.000000 — no new accuracy, and no regression; do not restate the criterion to make it pass. What prime's default changes is what a user gets by typing nothing: flagless PBMC P@100 0.5907 → 0.7062 for R_det 0.1911 → 0.1754, Kinnex ≥5-record concordance 0.6081 → 0.7647, decoy rate 0.3122 → 0.1300 — the one axis in the benchmark where atlas and long reads move together. **(a)** Version progression on the full call set, the output every version emits: PBMC atlas-agreement precision 0.1175 → 0.2030 → 0.2044 → identical and recall 0.1562 → 0.2979 → 0.3043 → identical, with the v2 → prime band exactly zero on every metric and every dataset. **(b)** The same at the pre-registered precision default (tier 1 ∩ internal-priming-pass ∩ ≥2 clip molecules): shipped is greyed out because it cannot emit this output at all (its BED score column is 0 everywhere), the hollow markers are v2 run with no behaviour flag — what a user gets by typing nothing — and the v1 → v2 precision deltas are printed at true size (−0.0105 PBMC, +0.0036 / +0.0018 mice). **(c, d)** The four versions in the precision/recall plane against the competitor panel, on PBMC 10k v3 **(c)** and GSE104556 testis **(d)**, with F1_det isolines, the pre-registered gate P@100 ≥ 0.50 and the 3-seed genic-shuffle nulls as ticks; circles are the full call set and diamonds the precision default, and prime is drawn as a ring because it lands exactly on v2. **(e)** Matched call count under each version's own shipped ranking, with tie-break exposure drawn: hatched bars are tie-decided and are not like-for-like (on PBMC at N = 46,544 v1 cuts at 1 clip molecule with 117,243 sites tied and only 2,131 kept, while v2 and prime cut at 2 molecules and keep 16,718 of 16,718). Same library, same budget, same code, only the ranking key differing: 0.7062 by clip molecules against 0.3857 by UMI depth — the clip evidence is what makes the ranking work. **(f)** Compute, two stacked axes: wall time above, peak resident set size below, both log; peak RSS falls 228.4 → 10.6 GB across v1 → v2 on the arms shown. **(g)** The reliability axis on the PBMC 10k v3 ≥2-molecule output: atlas-agreement precision beside Kinnex x3p long-read concordance at ≥5 and ≥20 UMI and the fraction of calls sitting at a Kinnex internal-priming decoy (lower is better). Caveats that travel: v1 → v2 is a bug fix, not an accuracy gain — PBMC atlas-agreement precision falls 0.0105 and Kinnex concordance falls with it, and it must be drawn and quoted as a correctness change; the flagless comparison (panels b, c, g) is not pre-registered and exists on PBMC 10k v3 only, so quote it as "what changes for a user who types nothing", never as a gain over the manuscript arm; prime is an unmerged branch that cannot retroactively become the pre-registered default, and nothing on this figure changes a manuscript number; atlas precision is atlas agreement, not truth; Kinnex truth is from donors other than either PBMC library and the two mouse libraries have no long-read truth, so panel g is human-only; shipped and v1 were never run on pbmc4k and no such run was fabricated; shipped cannot be ranked by clip molecules and therefore has no ≥2-molecule arm anywhere on this figure, which is a property of the pre-Stage-1 caller and not a gap in the benchmark; wall time is not comparable across version sets (v2 concurrent, prime sequential with BLAS pinned to one thread) — peak RSS is.
